1. The story in one minute

Train a small network on "what is (a + b) mod 23?" using only some of the pairs. It quickly gets every training pair right. On pairs it hasn't seen it does no better than guessing, and stays that way for thousands of steps. Then, with no change to the training setup, held-out accuracy shoots up to 100%. That delayed jump is called grokking.

The paper explains the delay. Weight decay keeps pulling the weights toward zero, so the network can never fit the training labels perfectly. A small leftover error remains. That leftover error keeps pushing the network's internal features in a direction that matches the task's hidden structure, here waves (Fourier modes) over the numbers 0 to 22. Once those features are strong enough, the network starts answering unseen pairs correctly.

The theory makes a concrete prediction: the waiting time is proportional to 1 / (learning rate × weight decay). Double the weight decay and grokking should come about twice as fast, as long as you stay inside the region where grokking happens at all.

We rebuilt their experiments from the paper text alone, since their code is not public, and tested that prediction along with several others.

2. The setup

The task

Every pair (a, b) with a, b in 0..22 gives 23 × 23 = 529 examples. The label is (a + b) mod 23. Each input is two one-hot vectors glued together: 23 slots with a single 1 marking a, then 23 slots marking b, for 46 numbers in total.

The paper splits train and held-out data in an unusual way. A pair goes to training if its difference (a − b) mod 23 is in a fixed set of 16 values. That gives 368 training pairs and 161 held-out pairs. The split doesn't change if you add the same number to both a and b, which keeps the cyclic symmetry intact. That symmetry is what makes the Fourier analysis clean.

The model

A one-hidden-layer network with 256 ReLU units and no bias terms: f(x) = W2ᵀ · relu(W1ᵀ x). It has 46·256 + 256·23 = 17,664 weights. The missing biases are deliberate: they make the network "homogeneous" (section 5).

Loss and optimizer

  • MSE loss: the 23 outputs are compared to a one-hot target with squared error, averaged over all 368 × 23 numbers. The paper uses MSE instead of cross-entropy because it makes the math linear.
  • Full-batch SGD: every step uses all 368 training examples. That removes sampling noise, so the run is deterministic.
  • Learning rate η: step size. The paper sweeps 0.1 to 100. Those values look huge, but the MSE averages over 8,464 numbers, so gradients are tiny.
  • Weight decay λ ("coupled L2"): every step also shrinks each weight by a factor of (1 − ηλ). In PyTorch that is SGD(weight_decay=λ). The update is w ← w − η(∇L + λw).

3. What grokking is

Normally, training and held-out accuracy rise together, or held-out stalls and you call it overfitting. In grokking they are separated in time. The paper sorts every (η, λ) setting into four outcomes after 24,000 steps, using a 90% threshold:

PhaseRuleIntuition
Grokkingfinal train > 90% and held-out > 90%memorized, then generalized
Memorizationfinal train > 90%, held-out belowgeneralization didn't arrive in time
Forgettingtrain crossed 90% earlier, ends belowweight decay too strong; it erodes the fit
No fittingeverything elsestep too big (unstable) or decay too strong

4. The neural tangent kernel, from scratch

Stack every output on every training example into one long vector f (368 × 23 = 8,464 numbers). The Jacobian J says how each of those numbers changes when you nudge each weight. It is an 8,464 × 17,664 matrix.

The NTK is K = J Jᵀ, an 8,464 × 8,464 matrix. Entry K[i, j] answers: if a gradient step reduces the error on output j, how much does output i move? Two examples with a large kernel value "share" learning. With plain gradient descent, the outputs evolve as:

df/dt = −K · (f − y)

If K stayed fixed through training, the network would behave like a fixed-feature kernel machine. That regime is called lazy learning. If K changes, the network is building new features: rich or feature learning. The paper's claim is that grokking is the network moving from lazy to rich, and that the leftover error is what drives the move.

For our one-hidden-layer net the kernel has a closed form, which we use instead of autograd because it is exact and fast:

⟨∇f_c(x), ∇f_d(x′)⟩ = [c = d]·⟨h, h′⟩ + (x·x′)·Σ_k W2[k,c]·W2[k,d]·m_k·m′_k

Here h is the hidden activation and m is the 0/1 pattern of which ReLUs are on. Our test suite checks this formula against PyTorch autograd.

5. Homogeneity: the trick the theory rests on

Multiply every weight by c. Each ReLU output scales by c, then the second layer scales by c again, so the output scales by c². That is 2-homogeneity: f(cθ) = c²·f(θ). It only works because there are no biases.

Differentiating that identity at c = 1 gives Euler's relation: J·θ = 2·f. Weight decay pushes the weights in the direction −θ. Pushing the weights by −θ moves the outputs by −Jθ = −2f. So weight decay turns into a simple term in output space, and the equations close:

dσ/dt = −(K + 2λ̃ I)·σ − 2λ̃·y, σ = f − y (the residual)

λ̃ is the weight decay rescaled by the loss normalization: λ̃ = λ·n·p/2, where n is the number of training examples and p = 23. We test both the scaling and the Euler identity to 1e-12 precision in tests/test_core.py.

6. The paper's argument, step by step

Step 1: weight decay leaves a ridge residual (Theorem 1)

Set dσ/dt = 0 with K held fixed:

σ* = −2λ̃ (K + 2λ̃ I)⁻¹ y → in eigendirection j: σ_j / y_j = −2λ̃ / (Λ_j + 2λ̃)

This has the same form as ridge regression. Directions the current features represent strongly (large eigenvalue Λ_j) are fit almost fully. Weakly represented directions keep a large share of their target as error. So after memorization, the error sits exactly in the directions the network hasn't learned yet.

Step 2: the residual reshapes the kernel

The kernel itself evolves through the "neural tangent hierarchy":

dK/dt = −K⁽²⁾·σ − 2λ̃·K

The first term says the leftover error changes the features. The second says weight decay shrinks the kernel. One pushes, the other pulls.

Step 3: collapse to two numbers

Modular addition has a natural basis of waves over 0..22. Project everything onto one task-aligned wave u. Λ = uᵀKu measures how strongly the network's features carry that wave, and σ = uᵀ(f − y) is the error along it:

dσ/dt = −(Λ + 2λ̃)σ − 2λ̃y, dΛ/dt = −aσ − 2λ̃Λ

a is a coupling constant. Since σ is negative after fitting, −aσ is positive, so the leftover error grows Λ. The system settles at a stable point with Λ* > 0 for task-relevant waves and Λ* = 0 for irrelevant ones (Theorem 2). That is how the network selects the right features.

Step 4: the slow clock

The error relaxes fast, while Λ moves on a time scale set by λ̃. Converting continuous time back to optimizer steps, the natural clock is:

τ = η · λ · (steps since fit)

Every quantity of the slow dynamics depends on steps only through η·λ·steps. So the number of steps until held-out accuracy rises is proportional to 1/(ηλ). This is the headline prediction (Fig. 3b).

Step 5: boundaries in the (η, λ) plane

  • Grok vs memorize: you need enough slow time within 24,000 steps, so roughly η·λ·T ≥ const, i.e. η* ∝ 1/λ.
  • Mode reachability: if λ is too large, the stable point Λ* drops below the strength needed to generalize, so the network never generalizes however long you wait (paper: λ ≈ 7e-4).
  • Training fit: even larger λ prevents fitting the training set (paper: λ ≈ 8.4e-4).
  • Stability: η above about 2 / (largest kernel eigenvalue) makes gradient descent diverge (paper: η ≈ 18.9).

Why the jump is sharp when Λ grows smoothly

A held-out example flips to correct when its margin crosses zero. If many examples cross at similar values of Λ, smooth growth in Λ produces a sudden jump in accuracy. Nothing discontinuous is needed inside the network.

Engineering lesson
Our first speed-up idea was to batch many networks into one process. Benchmarking showed it was slower per CPU core than one process per core, because these matrices are too small to use the hardware well. We kept the batched code since it is tested and convenient, but ran one single-threaded process per core. Measure before you optimize.

8. How we know the code is right

There is no official code to compare against, so we built checks at three levels.

  1. Unit tests (18 tests, pytest): split sizes and shift-invariance; no biases and 17,664 weights; f(cθ) = c²f(θ) and Jθ = 2f; batched trainer equals the plain trainer; runs in a batch don't affect each other; determinism; phase rules on hand-made curves; a synthetic 1/λ boundary is recovered; the closed-form NTK equals autograd.
  2. Exact numbers printed in the paper: the grokking cell crosses 90% at update 8,300, and the forgetting cell peaks at 0.948 train accuracy and ends at 0.204. Matching these to every printed digit is strong evidence that our reading of the setup (init, split, loss scaling, decay convention) is right.
  3. Scientific claims: the phase map, the 1/λ boundary, the timing law, NTK Fourier structure, the ridge residual and seed robustness. Section 9 has the results.

What surprised us

  • Two of our own metrics were fooled by the kernel's diagonal, which is 1 by construction after normalization. A matrix that is "1 on the diagonal, constant elsewhere" counts as perfectly circulant. Lesson: test a metric on a case where the answer should be zero.
  • A 4-operand einsum silently built a 6 GB intermediate and the process was killed by the out-of-memory killer with no Python error. Rewriting it as one matrix product cut peak memory from 7.4 GB to 2.9 GB.
  • The ridge formula is exact for a smooth network but only approximate for ReLU: SGD never reaches a stationary point. A controlled experiment (same setup, only the activation changed) pinned this down.
  • Learning rate and weight decay do not enter symmetrically in practice: the fitting stage costs ~1/η updates regardless of λ.

10. How to talk about it

"What did you do, in one sentence?"

I independently reproduced a September 2026 theory paper on grokking from its appendix, since the authors hadn't released code. I matched their printed numbers exactly and tested their main prediction, that grokking time scales as 1/(learning rate × weight decay), over a sweep of ~1,900 networks.

"What is grokking?"

Delayed generalization: the model fits the training set early, but held-out accuracy jumps much later with no change to training. It is a clean lab setting for studying when and why networks generalize.

"What is the NTK, simply?"

A matrix that says how training on one example moves the prediction on another. If it stays fixed, the network acts like a kernel machine with fixed features. If it changes, the network is learning features.

"Why does weight decay matter here?"

It stops the network from fitting the training data perfectly, so a small error remains. That error keeps reshaping the features until they match the task's structure. Weight decay also sets the clock: progress depends on steps × learning rate × weight decay.

"How did you make sure your code was right without the authors' code?"

Three levels: unit tests for the mathematical properties the theory relies on (homogeneity, Euler identity, closed-form NTK against autograd); exact matches to numbers printed in the paper; and only then the scientific claims, reporting where they did and didn't hold.

"What would you do next?"

Run the Transformer sweep and the NTK-alignment intervention from the appendix, try cross-entropy loss (outside the theory's assumptions), and measure the coupling constant a directly along a training run.

"What are the limits of this paper?"

The theory assumes homogeneous networks, MSE loss, full-batch gradient flow and a single decoupled Fourier mode. The boundary constants are fitted to the phase map, not measured from the kernel. The sweep uses one random seed.
